# App design sources

## What companies shipped in 2026
These are first-party accounts of product behavior, reviewed November 18, 2026. Each case pairs a release with a question to test in the current app. The release establishes what the company offered; user outcomes need separate evidence.

- **Linear, March 12.** Linear aligned headers, navigation and view controls across issues, projects, reviews and documents. Open two different object types in your app and try the same operation on each. Which control should stay in the same place, and which actions belong only to that object? [Linear UI refresh](https://linear.app/changelog/2026-03-12-ui-refresh) and [the designers’ account of the changes](https://linear.app/now/behind-the-latest-design-refresh)
- **Google Maps, March 12.** In its US rollout of Immersive Navigation, Maps used zoom and transparent buildings to expose an upcoming maneuver, then highlighted entrances and parking near arrival. When changing visual emphasis mid-task, check whether people can still locate themselves and identify their next action with reduced motion. [Google Maps launch](https://blog.google/products-and-platforms/products/maps/ask-maps-immersive-navigation/)
- **Spotify, May 28.** Spotify brought desktop playlist folders to mobile and began rolling out bulk editing inside playlists. Separate the need to carry an organizing model across devices from the choice of controls on each device. Can a listener organize several items on a phone and recognize that organization on desktop? [Spotify playlist and queue update](https://newsroom.spotify.com/2026-05-28/playlist-folders-mobile-queue-controls-updates/)
- **GitHub, June 25.** A public preview placed shared filtered issue views alongside personal shortcuts in a repository sidebar. People with triage access or higher could define a view for everyone. When someone saves a filter, can they tell whether it changes their own workspace or the team's? [GitHub saved views preview](https://github.blog/changelog/2026-06-25-saved-views-for-repository-issues-and-adjustable-row-heights-in-projects/)
- **Notion, August 19.** Enabling developer features exposed a sidebar destination for Workers, connections and run logs, plus a contextual bar for copying the current object's ID. For a specialist workflow, trace which tasks require an overview and which need the object already on screen. [Notion release notes, August 19 entry](https://www.notion.com/releases/2026-08-19)
- **Airbnb, September 30.** Its fall update described a travel map where people could explore connections' trips, open places and save favorites. Trip owners could choose which trips and details to share. For a shared discovery surface, trace both sides: can a viewer act on a place they discover, and can the owner control what the viewer sees? [Airbnb fall update](https://news.airbnb.com/airbnb-2026-fall-update)
- **GitHub, October 1 and November 10.** GitHub separated its work dashboard from its activity feed. After developers reported having to navigate away to see enough work, GitHub raised the default issues and pull requests shown from three to six, retained custom selections and hid the agent section for accounts without sessions. Compare a busy account with an empty one: can each identify its next action without opening another view? [October dashboard rollout](https://github.blog/changelog/2026-10-01-new-dashboard-experience-now-the-default/) and [November follow-up](https://github.blog/changelog/2026-11-10-a-more-informative-github-dashboard/)

## Applying the cases to a design decision
Start with the project’s accepted direction and the [UI designer’s principles](presets/ui-designer.md). Choose a case that shares the task, audience and constraint. Trace the case against the applicable design guidance. Identify the behavior it supports, a detail you would adapt for this product, and a check that would expose a poor fit.

- **Hierarchy and useful density.** Linear quieted surrounding navigation. GitHub gave work items more room on the dashboard by reducing padding. Try the proposed layout with a full queue and an empty account. Can someone spot a blocked item or the first available action? At enlarged text sizes, can they still distinguish similar titles and see keyboard focus?
- **Consistency and specialization.** Spotify carried playlist folders across devices. Notion put specialist controls beside the object they act on. Preserve familiar names and relationships across surfaces, then choose controls for the task and device. Can a returning user find the same item on mobile? With developer features off, does the everyday task remain clear? With them enabled, can a specialist act on the item without losing their place?
- **Personal and shared state.** A saved issue filter can affect a whole team. A trip can become visible to connections. Before saving, ask who the participant expects can see the result. Check the answer from the other role and verify what changes when the owner edits the setting.

## Navigation, state and usability
- For grouping and labels, distinguish discovering categories through card sorting from testing whether people can find an item in the proposed hierarchy. [Department for Education research example](https://user-research.education.gov.uk/about-this-website)
- For destination switching and changing window sizes, trace the selected item across the platform's navigation and layout patterns. [Apple tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) and [Android canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts)
- For a screen that displays the same object in several places, identify the owner of changing state and which values each view can derive. [Thinking in React](https://react.dev/learn/thinking-in-react)
- For web interactions, check the applicable keyboard, focus and status-message criteria. For an uncertain journey, give likely users a realistic goal and observe where they go. [W3C explanations of WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/) and [GOV.UK moderated usability testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing)

## Task boundaries and sequence
- Trace a task past the edge of the app. If someone submits a request here and receives the decision elsewhere, show where they can check progress and what marks completion. [GOV.UK Service Standard on solving a whole problem](https://www.gov.uk/service-manual/service-standard/point-2-solve-a-whole-problem)
- Decide whether people can choose their next task or must follow a sequence. For work that spans visits, check whether someone returning can tell what is complete and what they can do next. [GOV.UK Design System on completing multiple tasks](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/)

## External entry and durable links
- Trace entry from a notification or shared link as well as from inside the app. On Android, specify where Back and Up lead for that entry path. [Android deep-link navigation](https://developer.android.com/guide/navigation/design/deep-link)
- When moving an item to a new section, open a previously shared URL and verify it still reaches that item. Stable identifiers let navigation labels evolve without invalidating bookmarks. [Tim Berners-Lee on durable URIs](https://www.w3.org/Provider/Style/URI)

## Interrupted work and recovery
- If edits can be made offline, distinguish a local save from a successful sync. Ask engineering what survives closing the app, then check the status users see before and after reconnection. [Android offline-first architecture](https://developer.android.com/topic/architecture/data-layer/offline-first)
- When an answer fails validation, retain the entered values, identify the field and explain how to fix it. Walk through correction and resubmission to see whether the person can finish. [GOV.UK validation pattern](https://design-system.service.gov.uk/patterns/validation/)

## Navigating within a page
- Inspect the headings and named regions independently of the visual layout. Can someone navigating by heading or landmark locate the main task and distinguish repeated navigation regions? [W3C WAI page structure tutorial](https://www.w3.org/WAI/tutorials/page-structure/)
